# Rules

- Всегда пишем код по принципам DRY (Don't Repeat Yourself), KISS (Keep It Simple, Stupid), SOLID, PoLA (Principle of Least Astonishment), YAGNI (You Aren't Gonna Need It), ADP, CCP, REP, ACID .
- Всегда предлагаем подробный план (Implementation Plan) перед тем, как приступать к реализации любых изменений в коде.
- Используй context7 если нужно что-то найти в интернете. Если же ты не можешь найти ответ в интернете, то используй google.
- использовать создание task для планирования работы.
- When you need to search docs, use `context7` tools.
- не мменять стили css без спроса пользователя.
- все статичные локализации в ./messages/\*
- по возможжжности разделять отвественность компонентов и засорять компонент новой отвественность, лучше её вынести отдельно.
- пользователям нужны только рабочие поля без технического мусора.
- проверяй проекты написанные на js react node и тому подобное через oxlint
- проверяй проекты написанные на python через ruff (ruff check, ruff format)
- Запрещено добавлять hover-анимации смещения и масштабирования (transform: translateY, translateX, scale) на карточки, модалки и списки. Hover должен быть статичным по геометрии: допустимы только мягкая подсветка границ (border-color), плавное изменение фона (background) и свечения (box-shadow) без физических сдвигов элементов.
- Никогда не использовать символ тире «—» (em-dash) в текстах, описаниях, документации и коммитах (использовать дефис «-» или двоеточие «:»).
- Если нужно сделать график, диаграмму или сравнительную таблицу, делать их в виде отдельной интерактивной HTML/CSS/JS страницы в дизайне и стиле приложения freakcloud (стильный темный фон, золото, 0 border-radius), чтобы пользователь мог сделать оттуда красивые скриншоты для README/документации.
